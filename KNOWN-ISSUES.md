## Medium priority — production readiness

### Reports catalogue is incomplete
**Area:** Reports

Market Floor, Customer Statement, Outstanding Containers, Daily Movements, Weekly Movements, Movement History, Monthly Summary and Daily Print Pack are implemented. Monthly Summary and Daily Print Pack operator acceptance passed; BT-RPT-009/010 and BT-MF-006 remain explicit release decisions/validation rather than reopening those accepted workflows.

The Daily Print Pack cross-section snapshot gap is closed in normal schema17 runtime: both delegated numerical sections and their customer/container metadata share one read transaction. Deterministic concurrency evidence remains green, and bounded real preview/print plus Windows/operator acceptance passed.

### Dashboard is still the first-pass operational dashboard
**Area:** Dashboard

It shows Returned Today, Taken Today, Outstanding and Requires Attention. Requires Attention is quantity-focused and there is no drill-down/recent activity/operational attention list yet.

### Business branding is text-only
**Area:** Business Information / Generated Output

Business Information supports Business Name, Trading Name and Default Report Header, and current PDF reports use that identity. Logo storage/rendering and a shared branding layer for reports/email are not implemented yet.

### Email/SMS controls are preferences only
**Area:** Communications

Customer reminder preferences and the `ReminderDelivery` persistence model exist, but no real Email or SMS provider/send workflow has been implemented.

### Movement correction/reversal bounded Task20 acceptance is complete
- Alpha.9.10 completed the bounded Items 1–8 Windows/operator inventory, including correction/disposition dialogs, native Administrator review and forensic drill-through, real concurrent multi-window stale-state handling, and the required 1920x1080/150% plus larger-effective-workspace DPI matrix.
- Opening Adjustment and Excel Import generic correction/reversal remain blocked as required.
- BT-CORR-033 and BT-HIST-008/009 are accepted from the complete criterion/evidence reconciliation. Actual production-database recovery and general candidate/release UI regression retain their own statuses.
**Area:** Movements / Audit

### Container display order permits duplicate priorities
**Area:** Container Types

Multiple active Container Types can currently be saved with the same configurable Display order, making their relative order depend on a secondary name sort. Preserve manual reordering and do not hard-code Blue/Yellow priorities; a dedicated follow-up must define deterministic conflict handling and reorder UX.

### Production Backup / Restore is missing
**Area:** Operations

Developer Database Backup/Load/Fresh tools are for testing only. A production-safe user backup/restore/recovery workflow is still required.

### Batch Entry recovery/polish requires operator smoke acceptance
**Area:** Batch Entry

Batch Entry Continue/Save/Discard crash/restart recovery is implemented, and the historical alpha.24.2.24 record says the general three-action flow was operator-confirmed. That record does not explicitly prove every BT-BATCH-010/011 clause, including all removal/failure/same-process conditions, so both rows remain `IMPLEMENTED-STATIC` and the active checklist retains targeted recovery acceptance. The separate security gap is ownership: the current persisted draft format is installation-scoped and can surface one signed-in user's unfinished draft to another user on the same installation. Security Batch E fixes BT-SH-012 and implements BT-BATCH-012's stable persisted user-ID ownership, owner-only Continue/Save/Discard and fail-closed enforcement below WinForms; Administrator role does not bypass ownership. Existing implemented recovery and separate role authorization for committing a batch remain unchanged.

### Multi-computer production use is not supported yet
**Area:** Deployment

SQLite is currently configured for local single-PC operation. A central provider/concurrency strategy is required for simultaneous multi-computer use.
