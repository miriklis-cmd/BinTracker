# BinTracker Current Release Notes

## v0.4.0-alpha.19.10

### Relational Import movement provenance

`BinMovement` now has a nullable `ImportRunId` relationship.

New import behaviour:

- every opening Adjustment created by Step 4 links to the current ImportRun;
- every imported OUT/IN movement links to the current ImportRun;
- Manual/Batch movements remain unlinked;
- an index supports fast lookup of all movements generated by a particular ImportRun;
- deletion of an ImportRun is restricted while linked movements exist.

### Existing alpha database upgrade

SQLite migration V10 adds the nullable column/index and safely backfills eligible imports made by earlier alpha.19 builds.

Backfill is deliberately conservative. It links only movements that:

- have source `ExcelImport` or `Adjustment`;
- have a strict `IMPORT-<numeric run id>` reference;
- resolve to an existing ImportRun.

Manual/Batch movements are never inferred into an ImportRun.

### Tests / documentation audit

Integration coverage now verifies:

- all movements generated by a successful import share the correct ImportRunId;
- normal Manual movement remains NULL;
- migration V10 exposes the FK/index;
- legacy import-reference backfill does not link a Manual movement.

The active Known Issue for missing relational provenance has been removed and the Roadmap/Test Checklist/Re-import Safety documentation reconciled.
